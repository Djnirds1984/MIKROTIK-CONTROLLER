# MikroTik Controller — Ubuntu / Debian deployment

This guide installs **mikrotik-controller** on a small x86 mini PC running
Ubuntu or Debian, runs it as a `systemd` service behind a local
PostgreSQL database, and survives reboots.

## Requirements

| Component | Version | Notes |
|-----------|---------|-------|
| OS        | Ubuntu 22.04+ / Debian 12 | amd64 (x86_64) |
| PostgreSQL | 12+ | Only dependency at runtime |
| Network    | Ports `8080` (UI) + `5432` (Postgres) | open on the mini PC |

The app is a single **statically-linked, pure-Go binary** (no runtime, no
`glibc` extras beyond libc). All UI templates and static assets
(`/static/*`, `/templates/*`) are **embedded at build time** — only the
executable is needed at runtime.

### Pre-built binaries
Release artifacts are published for these platforms (built with
`CGO_ENABLED=0`, so they run on any glibc musl-free distro):

```
linux-amd64     → x86_64 mini PC (most common)
linux-arm64     → Raspberry Pi 4/5, RockPi, etc.
linux-arm (armv7) → Raspberry Pi Zero 32-bit, Orange Pi
```

## Quick start (copy-paste)

SSH into the mini PC (no monitor required) and run from a clone of this repo:

```bash
# 1. Provision PostgreSQL (installs it if missing, creates role + DB)
sudo ./deploy/setup-postgres.sh

# 2. Install & start the service (builds natively if no binary is supplied)
sudo ./deploy/install.sh

# 3. Point a browser at the mini PC's IP, port 8080
#    e.g. http://192.168.1.50:8080/
```

You're done. The service auto-starts on boot and restarts on crash.

## What the installer does

`deploy/install.sh`:
- Requires `root` (uses `sudo`).
- Uses a pre-built binary if you pass one (`./deploy/install.sh build/mikrotik-controller-linux-amd64`);
  otherwise, if `build/mikrotik-controller-linux-amd64` exists it uses that;
  otherwise it falls back to **building natively** on the mini PC (requires Go).
- Installs the binary to `/opt/mikrotik-controller/mikrotik-controller` (mode `0755`).
- Copies the `firmware/` reference files alongside (for configuring MikroTik routers).
- Creates an unprivileged system user `mikrotik` (no login shell, no home).
- Installs `/etc/default/mikrotik-controller` (only if absent — safe to re-run).
- Installs `/etc/systemd/system/mikrotik-controller.service`.
- `systemctl daemon-reload`, `enable`, `restart`.
- Reports status + the correct URL + a pointer to `journalctl`.

## Configuration

Edit `/etc/default/mikrotik-controller` and restart:

```bash
sudo systemctl restart mikrotik-controller
sudo journalctl -fu mikrotik-controller
```

| Variable | Default | Description |
|----------|---------|-------------|
| `MIKROTIK_PORT` | `8080` | TCP port the web UI listens on. |
| `PISOWIFI_DB_HOST` | `localhost` | PostgreSQL host. |
| `PISOWIFI_DB_PORT` | `5432` | PostgreSQL port. |
| `PISOWIFI_DB_USER` | `pisowifi` | Database user. |
| `PISOWIFI_DB_PASSWORD` | — | Database password (auto-generated by `setup-postgres.sh`). |
| `PISOWIFI_DB_NAME` | `pisowifi` | Database name. |

> The schema is created automatically on first boot by the app's built-in
> migrations (`internal/config/database.go`). No manual SQL is needed — point
> the app at a **fresh, empty** database.

## PostgreSQL

`deploy/setup-postgres.sh` is idempotent:
- `apt-get install`s `postgresql` if missing.
- Creates a strong random password if none is set, and writes it to
  `/etc/default/mikrotik-controller`.
- Creates the `pisowifi` database owned by `pisowifi`.

Typical standalone usage:
```bash
sudo ./deploy/setup-postgres.sh
sudo ./deploy/install.sh
```

## Removing it

```bash
sudo ./deploy/uninstall.sh          # keep PostgreSQL data
sudo ./deploy/uninstall.sh --purge  # also DROP DATABASE / DROP ROLE
```

## Building the Linux binary yourself

From any Linux/macOS/Windows machine with Go:

```bash
make release          # builds all: linux-arm, linux-arm64, linux-amd64
# or just the amd64 binary the mini PC needs:
make linux-amd64
```

Cross-compiling from **Windows** (this produces the same file the mini PC uses):
```powershell
$env:GOOS="linux"; $env:GOARCH="amd64"; $env:CGO_ENABLED=0
go build -o build/mikrotik-controller-linux-amd64 .
```

## Firewall (UFW)

If the mini PC is internet-facing, lock it down to the LAN:

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8080
# PostgreSQL on 5432 should stay localhost-only; the mini PC talks to it locally.
```

## systemd notes

- Logs stream to `journalctl -fu mikrotik-controller` (stdout/stderr).
- On Windows-like "exe opens and immediately closes" behavior: under systemd the
  equivalent symptom is `systemctl status mikrotik-controller` showing the unit
  `failed` (usually wrong DB password or port 8080 already in use).
  `install.sh` detects this and points you at `journalctl`.
- The service uses `ProtectSystem=strict` with `ReadWritePaths=/opt/mikrotik-controller`,
  and runs as the non-root `mikrotik` user.
